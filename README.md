# ContractLens

A focused document question answering app for text-based PDF contracts. It extracts text with page numbers, divides pages into passages, embeds them locally with Sentence Transformers, retrieves relevant passages by cosine similarity, and asks a Groq-hosted LLM to answer using those passages. Answers request `[S1]`-style citations, and the interface displays the original filename, page, passage, and similarity score.

This is an original implementation created for Harshit Kalra. It uses open-source packages and the Groq API; it does not incorporate code from the reference GitHub repositories.

## Features

- Upload multiple PDF contracts and choose which documents to search.
- Inspect exact retrieved passages and page numbers beside an answer.
- Extract parties, effective date, payment terms, termination, and governing law.
- Process uploaded PDFs in memory in the app session; no document database is required.
- Rebuild the in-session index automatically when uploaded files change.

## Setup (Windows PowerShell)

Use Python 3.11. The first run downloads a local embedding model. A Groq API key is required for generated answers; retrieval works without a key.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` to set `GROQ_API_KEY`, then run:

```powershell
streamlit run app.py
```

Do not commit `.env` or your API key. Open the displayed local URL, upload PDFs from `samples/`, select **Process documents**, and ask a question. Run the offline core tests with:

```powershell
python -m unittest discover -s tests -v
```

## Architecture

1. `extract_pdf_pages` reads selectable text with PyMuPDF and keeps page numbers.
2. `chunk_pages` splits each page, so a passage cannot cite the wrong page.
3. `VectorIndex` embeds passages once and compares their normalized vectors with a question.
4. `answer_question` sends the top passages and their labels to Groq, requesting a grounded answer.
5. Streamlit shows the answer and exact source passages. Key terms reuse the same retrieval and answer path.

## Limits

- Scanned/image-only PDFs need OCR and currently return a clear error.
- Source labels are generated by an LLM. The app exposes supporting text but does not formally prove every claim; verify answers against the cited PDF.
- Embedding similarity is relative to the indexed documents and is not a calibrated confidence score.
- Files and indexes are kept in server memory during the app session, not persisted across restarts. Running this as a public multi-user service would require access control and stronger isolation.
- Uploaded passages are sent to Groq when generating an answer; use sample or authorized documents.
